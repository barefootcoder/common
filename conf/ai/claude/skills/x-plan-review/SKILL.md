# Plan Review Skill

Reviews an implementation plan by spawning multiple subagents under
different prompt variants, then synthesizes their reports into an
actionable checklist for plan revision. The variants were selected
empirically — see the experimental data at
`/var/local/CE-src/aidoc/ticket-docs/CLASS-990/prompt-experiment/` for
the rationale.

## Invocation

`/x-plan-review {{ARGS}}`

`{{ARGS}}` should be a path to a markdown plan file. If no argument is
provided, ask the user for the plan path before proceeding. Do not
guess.

## Outputs

Given a plan at `<plan-dir>/<plan-name>.md`, this skill produces:

1. **`<plan-dir>/plan-updates.md`** — clean, actionable checklist for
   updating the plan. The primary user-facing artifact.
2. **`<plan-dir>/plan-review/synthesis.md`** — detailed
   finding-by-finding analysis with evidence.
3. **`<plan-dir>/plan-review/reports/{variant}-run-{N}.md`** — the 8
   raw subagent reports.
4. **`<plan-dir>/plan-review/prompts/{variant}.md`** — substituted
   copies of the prompts that were used (for reproducibility).
5. **`<plan-dir>/plan-review/README.md`** — brief description of the
   run.

Existing outputs at these paths are overwritten without warning.

## Workflow

### Step 1 — Verify the plan path

Confirm the argument is an existing readable file. If not, report the
error to the user and stop. Do not improvise (don't search for similar
files, don't suggest alternatives without being asked).

Resolve to an absolute path; use that absolute path everywhere below.

### Step 2 — Compute output paths

Given absolute plan path `<plan_path>`:

- `plan_dir` = `dirname <plan_path>`
- `plan_basename` = `basename <plan_path>` (e.g. `plan=mece-migration.md`)
- `subdir` = `<plan_dir>/plan-review`
- `prompts_dir` = `<subdir>/prompts`
- `reports_dir` = `<subdir>/reports`
- `action_list` = `<plan_dir>/plan-updates.md`
- `synthesis_path` = `<subdir>/synthesis.md`
- `readme_path` = `<subdir>/README.md`

### Step 3 — Create the directory structure

```bash
mkdir -p <prompts_dir> <reports_dir>
```

### Step 4 — Save substituted prompt copies and README

The 4 review-variant templates and the synthesis template live in this
skill's `prompts/` subdirectory at
`~/.claude/skills/x-plan-review/prompts/`:

- `02-find-problems.md`
- `04-step-through.md`
- `05-confidence-graded.md`
- `07-failure-mode-checklist.md`
- `synthesis.md`

For each of the **4 review variants**, read the template, substitute
`{PLAN_PATH}` with `<plan_path>` (use a placeholder for `{REPORT_PATH}`
since each run has a different report path), and write the result to
`<prompts_dir>/<variant>.md`. The saved copies are for the user's
later reference; the actual prompts sent to agents (with full
`{REPORT_PATH}` substitution) are constructed in Step 5.

Write a `README.md` to `<readme_path>` with this content (substitute
`{PLAN_BASENAME}` and `{PLAN_REL}` where `{PLAN_REL}` is the plan
filename relative to the subdir, i.e. `../<plan_basename>`):

```markdown
# Plan Review: {PLAN_BASENAME}

[Created and submitted by AI: Claude]

Target plan: [{PLAN_BASENAME}]({PLAN_REL})

## What's here

- [`synthesis.md`](synthesis.md) — detailed finding-by-finding analysis
- [`reports/`](reports/) — raw outputs from the 8 review agents
- [`prompts/`](prompts/) — the prompts used (4 review + 1 synthesis)
- The clean action list is at [`../plan-updates.md`](../plan-updates.md)

## How it was generated

Generated by the `/x-plan-review` skill: 4 prompt variants × 2 runs = 8
review subagents, plus 1 synthesis subagent. See [`prompts/`](prompts/)
for the exact prompts used.
```

### Step 5 — Launch 8 review agents in parallel

For each of the 4 variants and each of 2 runs (run-1 and run-2),
construct the full prompt by reading
`~/.claude/skills/x-plan-review/prompts/<variant>.md`, substituting
both `{PLAN_PATH}` (with `<plan_path>`) and `{REPORT_PATH}` (with
`<reports_dir>/<variant>-run-<N>.md`).

**Launch all 8 in a SINGLE message** containing 8 parallel Agent tool
calls. This is essential — it gives the strongest isolation guarantee
(no agent can see another's output). Do not batch them across multiple
messages.

For every Agent call:

- `subagent_type`: `general-purpose`
- `description`: brief, e.g. `"Plan review (<variant>, run <N>)"`
- **Do NOT specify `model`** — agents inherit the session's model.
- **Do NOT set `run_in_background`** — keep all agents in the
  foreground so the skill blocks until all complete.

Wait for all 8 results.

If any agent fails to produce its report file at the expected path,
report the failure to the user and stop. Do not relaunch; do not
improvise.

### Step 6 — Launch the synthesis agent

Read `~/.claude/skills/x-plan-review/prompts/synthesis.md`, substitute
all four placeholders:

- `{PLAN_PATH}` → `<plan_path>`
- `{SUBDIR}` → `<subdir>`
- `{SYNTHESIS_PATH}` → `<synthesis_path>`
- `{ACTION_LIST_PATH}` → `<action_list>`

Launch a single Agent call with `subagent_type: general-purpose`, no
`model`, no `run_in_background`.

The synthesis agent writes both `<synthesis_path>` and `<action_list>`
in one pass.

### Step 7 — Report to the user

State plainly:

- Path to the action list (the primary artifact)
- Path to the synthesis (for digging deeper)
- A rough count of items in the action list, broken down by severity
  (read the action list to count)

Do not summarize the findings themselves — the user can read the file.

## Failure handling

Per project policy: **stop on failure, do not improvise.**

- Plan path doesn't exist or isn't readable → report and stop.
- A review agent fails to produce its report → report which one, stop;
  user decides whether to rerun.
- Synthesis agent fails → report; the 8 raw reports are still on disk,
  the user can recover or rerun synthesis manually.

## Notes for maintainers

- Variants were selected based on an experiment at
  `aidoc/ticket-docs/CLASS-990/prompt-experiment/`. Don't add 01
  (bare-evaluate) or 03 (explain-concerns) — they were dropped for
  redundancy with 02 and 04. Don't add 06 (steel-man) — it had the
  worst recall and was the only variant to produce a fabricated
  finding.
- The "do not pad the list" nudge in every variant template is
  load-bearing — keep it.
- 07 (failure-mode-checklist) uses generic categories, not
  data-migration-specific ones. If you re-specialize for a particular
  plan type, fork the template, don't replace the generic one.
- The synthesis prompt produces both `synthesis.md` AND the clean
  `plan-updates.md` action list in one pass; keep them in sync if you
  change the format of either.
